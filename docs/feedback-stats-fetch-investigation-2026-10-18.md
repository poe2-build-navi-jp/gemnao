# 匿名投票集計の取得失敗：調査と取得処理の改善

## 確認できた事実と未確定事項

依頼元から提供された証拠：

- 2026-10-18 10:05:22 JST（01:05:22 UTC）のcurl GETは200、no-store、`rows=[]`、`methods=[]`、`stepResultsAvailable=true`。対象は `game=valorant` のみ。
- Python側の01:05:40.547649 UTCは **urlopen直前の要求開始時刻**。403の受信時刻ではない。別途事前保存されたログが存在する場合に限り、01:05:40〜45 UTCを中心に照合する。
- 元処理はThreadPoolExecutor(max_workers=4)へ179件を投入。拒否時の停止・取消分岐がなく、失敗応答の本文・ヘッダー・最終URLを保存していない。ディレクトリ未作成の保存処理も問題。
- 179件のURLは正常なASCII slug。元コードに明示headersはなく、点検時のPython既定UAはPython-urllib/3.12、既定のリダイレクト追従、TLS検証有効、対象に適用されるHTTPSプロキシ設定あり（値は未読）。curlには独自UA・認証・Cookie・proxy override・redirect指定なし。

これらは **User-Agent、並列数、プロキシのどれが403の原因だったかの証明ではない**。200のあと403だったことだけでは拒否層を特定できない。

現リポジトリの `app/api/feedback/route.ts` GETはゲーム確認404または集計JSONを返す処理で、403分岐・コミュニティ報告の128件制限はない。`cloudflare/worker-source.mjs` にも当該GET専用の拒否分岐はない。GET経路にあるD1読み取りはエラーになり得るが、今回の403の発生元を示す証拠はない。

元の179件スクリプト・当日の失敗応答・Cloudflareのリクエスト/セキュリティログはこの保存環境で発見できなかった。ログインすれば当時のPages Functions標準ログを回収できる、という以前の案内は訂正する。認証を代行・回避していない。過去の別調査の403ログを今回の根拠には流用していない。プロキシ設定値・資格情報は読んでいない。現在の正規アクセス再開が確認できないため、本番GETを追加実行していない。

## ログ保存範囲・ログイン・Metricsについての訂正

[Cloudflare公式：Debugging and logging / Limits](https://developers.cloudflare.com/pages/functions/debugging-and-logging/#limits)（2026-10-18確認）は、Pages Functionsの標準ログは保存されず、リアルタイムのストリーム表示であると明記している。今からダッシュボードへログインしても、過去10:05の標準ログは回収できない。別途事前に保存されたログや当時の応答記録がない限り、元のfeedback GETの403原因は未確定のままである。「本人ログイン待ちで過去の標準ログを照合できる」とは案内しない。

依頼元の追加報告では、クラウドブラウザはGoogleログイン失敗後、本人承認のメールログインもlogin APIの403で拒否された。一方、本人の端末ではログイン可能。このlogin APIの403は元の `/api/feedback` GETの403とは別のエラーであり、同一原因・同一拒否層の証拠として扱わない。

本人提供のMetrics画像は成功5868・Errors 0との報告。これは当該feedback GETの到達・成功や、403が存在しなかったことを証明しない。対象リクエストを識別する当時の記録がないため、集計表示だけから元403の不存在・原因解消を判断しない。

この訂正は調査文書のみ。本番アクセス、再現リクエスト、ログイン再試行、取得コード・セキュリティ設定の変更は行わない。

## 取得側の変更

`scripts/collect-feedback-stats.py` を追加した。元ファイルがないためその場の修正ではなく、日次処理から呼べる置換用。サイトの実装・DB・設定の変更は不要で、今回変更していない。

- 指定された識別UA `gemnao-stats/1.0` を固定。GETだけ。TLS検証・既定の環境プロキシを維持。Cookie・認証・IP/経路切替なし。
- 完全逐次取得、要求間1秒、urllibの通信タイムアウト15秒、応答読取上限256KiB。タイムアウトは通信待機に対するもので、全体実行時間の保証ではない。
- 403・401・429・リダイレクト・他HTTPエラー・通信失敗・不正データの **最初の1件で全体停止**。自動再試行なし。Locationを追わず、後続の取得も行わない。
- 要求開始／応答ヘッダー受信／本文読取完了の時刻を区別。HTTP status、限定したヘッダー、固定要求と一致する最終URL、本文の長さ・SHA256・既知の拒否文言の有無を保存。本文・例外文・Cookie・Location・秘密やプロキシURLは保存しない。ヘッダーや文言は手掛かりであり、発生元は`unconfirmed`のままにする。
- 保存先ディレクトリを作成し、新規ファイルのみ書込（0600）。既存出力は通信前に拒否し上書き・追記しない。
- 入力contextを重複排除、topic重複・負数・非整数・不正JSONを拒否。成功contextだけの合計、取得失敗を含む未取得context、completeフラグを保存。部分取得は終了コード2。失敗を0件として扱わない。
- 集計は **累積回答のスナップショット**。人数でも日次増分でもない。rowsとmethodsは同じ回答を表し得るため加算しない。methodsは旧topicを識別できない場合があるため、方法別の全体合算も行わない。別日のスナップショット同士も加算しない。

## 日次タスクへの接続

正規アクセスが確認された実行環境で、元処理の検証済み179キーをJSON配列として渡す。サイト全体の列挙を推測生成しない。

```sh
python scripts/collect-feedback-stats.py \
  --contexts /path/to/verified-contexts.json \
  --output /path/to/daily/2026-10-18.json
```

出力ファイルが既に存在する場合は自動で別名にして再取得せず、既存結果を確認する。拒否後にUAや経路を変えて再試行しない。`complete=true`でも「指定したcontext集合」の完了であり、サイト全体の網羅性は入力一覧の確認が必要。日次タスク自体の呼出元はこの環境にないため、置換接続は依頼元で必要。今回スケジュール・受付設定は変更していない。

## 検証と集計範囲

`python -m unittest discover -s tests/feedback-stats -v`：9テスト成功。すべてメモリ上の合成応答、ネットワーク・本番API・投票POSTなし。拒否後のリクエスト数1、逐次間隔、部分結果、情報漏洩防止、重複排除、別次元の非加算、タイムアウト、不正応答、既存ファイル拒否、ディレクトリ作成を確認。

今回新たに取得した本番集計は **0 context**。実数として確認済みなのは依頼元の01:05:22 UTC時点のvalorantの空配列だけであり、179件全体が0件という意味ではない。

根本原因確定には、上記時間帯に別途事前保存された許可済みログや当時の応答記録が必要。現在開始する標準ログのストリームや今後の診断記録で、過去の403原因を遡って確定することはできない。セキュリティ変更・権限追加・新資格情報・課金を前提にはしない。失敗応答が残っていない過去の403は、取得側修正だけで原因を確定・解消済みと報告しない。
