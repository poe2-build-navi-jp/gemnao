# 報告管理「一覧を読む」の表示不具合（公開前レビュー）

## 再現

本番の認証・報告本文へアクセスせず、既存UIをローカルChromiumで模擬応答に接続。

- HTTP200・空配列：読込完了表示がなく、押す前と同じ空一覧になる。
- 401・403・503：すべて「審査は未設定、または管理者認証が必要です。新しい鍵は作成しません。」になる。HTMLエラー応答もJSON解析の失敗として同じ表示になる。
- 読込中はボタンが無効になるだけで、文言は変わらない。繰り返し失敗すると同一の文なので無反応に見える。
- 次ページ読込失敗時は古いnextカーソルが残る。

親ブラウザで見た共通エラー文だけから、HTTP状態やユーザー端末の原因は確定できない。空表示は0件の証拠ではない。

## 修正

一覧読込みの表示だけを変更。ボタンと直下のライブ領域に読込中を表示し、空結果・今回のページ件数・401/403/429/503/その他HTTP・不正JSON・通信失敗・10秒タイムアウトを4言語で区別。エラー本文は表示・記録しない。開始時に古い結果とnextを消す。既存の単一要求ガードを維持。`AbortSignal.timeout`の対応状況に依存しないAbortController＋タイマーへ置換し、終了時にタイマーを解除、アンマウント時に中止する。

GETには既定動作と同じ `credentials: same-origin` を明記。API・Cookie・認証判定・審査操作・権限・設定は変更しない。

## 正規ログインと設定名（値未確認）

- `/admin/discord-servers` の既存ログインを同一ブラウザ・同一サイトで行い、`/admin/reports` に戻って「一覧を読む」。既存CookieはHttpOnly、SameSite=Strict、path=/、HTTPSでSecure、有効期間8時間。JSでCookieを読む必要はない。
- APIの401条件は `REPORTS_REVIEW_ENABLED` が有効条件を満たさない、または既存管理認証が不成立。401だけでは両者を区別できない。既存認証は `DISCORD_ADMIN_TOKEN_HASH` / `DISCORD_ADMIN_TOKEN` の設定を使うが、値を取得・表示しない。
- 本人の最小操作は、必要な場合だけ通常の管理ログインを本人が入力すること。成功後も401なら、運用担当がデプロイ対象の `REPORTS_REVIEW_ENABLED` と既存認証の連携を確認する。今回は設定の値確認・変更、鍵の作成/転記は実行しない。
- 503はサービスやbindingなどの問題も含むため認証失敗と断定しない。関連構成名は `REPORTS_DB`、`REPORTS_GUARD`、`REPORTS_GUARD_INSTANCE`、`REPORTS_BUDGET_MODE`。403は拒否として止め、別経路で迂回しない。429は読込制限であり連打しない。
