# PCゲーム無料トラブル診断 β

## 実装対象

既存のゲムなおに `/diagnose` を追加する。P0は「起動しない・クラッシュ・黒い画面・フリーズ・低FPS・カクつき」の6症状。Windowsアプリ、ログ取得、AIチャット、課金、P1専用診断、ゲーム別診断は含めない。ゲーム名は端末内メモのみで、ゲーム固有の判定にはまだ使わない。

1. トップと関連する既存記事から、ネイティブリンクで診断へ移動
2. 症状 → PC全体かゲーム単体か → 症状別状況 → 必要時のみエラー分類 → 直前の変更 → 起動元 → PC情報 → 任意のゲーム名 → 実施済み対処
3. 原因の確率でなく、理由を伴う確認順（最大3件）を表示
4. 端末内で「未実施・試した（結果未確認）・改善した・改善しなかった」を記録
5. 任意の共有はプレビューと確認チェックを経て発行
6. 所有者の管理画面で、実施結果のプレビュー更新・即時失効・削除

通常8問、エラー分類が必要な場合9問。実施済み対処は関連候補を最大3件だけ先に表示し、その他は任意の折りたたみで選べる。PC全体の異常では2問で安全案内へ切り替える。固定の「3/7」は表示しない。「約1分」は利用者操作時間の検証前なので表示しない。

- `lib/diagnosis/rules.ts`: 対処・根拠・適用/除外条件・優先度。画面から独立
- `lib/diagnosis/validation.ts`: サーバー側の選択肢/形状の検証、共有スナップショット生成
- `lib/diagnosis/local.ts`: 端末内保存と最小限のAPI/計測呼び出し
- `lib/diagnosis/server.ts`: D1、権限、CSRF、回数制限、失効、削除、集計、定期処理
- `components/diagnosis-*`: 質問・結果・共有確認・閲覧/管理・CTA
- `app/diagnose`, `app/diagnosis`: 案内/診断、共有、管理、保存説明
- `migrations/diagnosis/0001_diagnosis.sql`: 診断専用の追加migration

- `docs/diagnosis`: 本書、ルール、保存、公開復旧、検証資料

## 進行・失敗時の仕様

1画面1質問（PC情報は1つの環境確認画面にWindows/GPU分類/メモリの選択をまとめる）。技術質問は「分からない」と確認方法を持つ。前の回答を変更したら依存する後続回答・対処記録・共有との紐付けを破棄する。既に作成した共有そのものは勝手に消したり更新したりしない。

端末内の記録はlocalStorage。再読み込みは「続きから再開」を選ぶ。保存拒否時は警告し、その画面のメモリ内で続行できる。前/次は診断専用ボタン。ブラウザの戻るはページ移動であり、戻ったときに端末内の続きへ再開できる。

共有保存エラーでは入力・確認内容を保持し、成功表示しない。二重クリックはロックし、再試行は同じrequest IDを使う。初回レスポンスだけ失われた場合、既存の同じ共有URLを返すが、ハッシュしか持たない復元用管理キーは再表示できない。この場合は明示的な警告を表示する。

## UI/SEO/広告

既存配色・WikiHeader/Footerを再使用。モバイルで押しやすい選択肢とフォーカス表示。記事本文や既存metadata、既存広告タグ、robots設定、URLは保持し、関連箇所へCTAのみ追加。

`/diagnose`は検索対象。既存sitemapの236件を保持し、この1件だけ追加。薄い症状別ページは作らない。個別共有・管理・APIはnoindexでsitemap対象外。共有OGPは汎用文で、回答をHTML metadataへ埋め込まない。回答内容の表示はAPI取得後のみ。

診断関連ページでは広告・GAを読み込まない。rootのインラインGA初期化もパス除外し、ローダーと計測ヘルパーも除外。記事からはフルドキュメント遷移。PagesレスポンスはCSPで外部スクリプト/通信/フレームを許可せず、Referrer-Policy:no-referrerを設定。`cloudflare/worker-source.mjs`の既存静的配信/記事キャッシュは維持。診断ページ・APIはprivate,no-store。

## 利用計測の解釈

有効化時のみ自サイトD1へ、start/complete/step/leave/article/record/create/copyを集計する。回答全文・自由入力・共有URL・秘密情報は送信しない。stepは到達した画面、leaveはその画面から離れた操作で、分岐や再訪があるためユニーク利用者数や厳密な離脱率ではない。copyはコピー操作数で、共有先の人数ではない。

recordは利用者の自己申告操作。未回答を「改善しなかった」に算入しない。複数の対処を続けて行った場合、どの対処が原因かは確定できない。集計でルール順位を自動変更しない。より詳しい解決実績の分析は共有スナップショットを適切な同意/保存設計で扱う将来の作業。
