# ゲムなお PCゲーム診断 0.6.0（Windows x64・試作版）

任意のWindowsゲーム本体EXEを選び、症状に応じた共通の確認・記録・手動再テストへ進むローカルアプリです。Wildsは任意のゲーム固有ルールの1つです。

**EXEは実際にコンパイル済みですが未署名です。0.6の英語/日本語画面・変更後の処理はWindows実機で未検証です。すべてのゲーム/症状の原因を自動特定し、修復できる完成製品ではありません。**

## 0.6の英語・日本語切替

- 上部の「Language / 言語」で English / 日本語を選べます。Windowsの表示言語が日本語なら日本語、それ以外は英語で起動します
- 選択は今回の起動中だけ。新しい設定ファイルは保存しません。計測/取得中は切替できません
- 待機中に切り替えても、ゲーム・症状・回答・同意・取得事実・比較元・手順履歴・PC全体の異常の注意を保持します。再取得/新しい再テストは行いません
- 質問、診断結果、注意、手順、履歴表示、TXTレポート、JSON保存説明を選択言語で表示。JSONのキー/結果コード・履歴スキーマ2・手順IDは共通です
- 端末名/DLL名などの取得原文は翻訳せず、原文であることを明記します。不明値は言語から独立した状態で保持します
- 英語版のガイドがないリンクは日本語ページを維持し、英語表示時に「Japanese」と明記します
- English instructions: `README.en.md` / `docs/QUICKSTART.en.txt`

## 対応範囲を先に確認

- 入口: 起動できない、クラッシュ・途中で終了、黒い画面、フリーズ・応答しない、FPSが低い、カクつく・一瞬止まる、その他・分からない
- 共通取得: 選択EXEに対応するWindowsのクラッシュ/応答停止、同時間帯の描画復旧/正常でないPC終了、取得時点のOS/CPU/GPUドライバー/RAM/空き容量、本体版/互換性登録
- 症状ごとに別の確認プランを表示。低FPS/カクつきは本人の同じ場面・1設定ずつの比較を案内します。**FPS、フレーム時間、GPU使用率、温度は計測しません**。ログ件数で性能改善を評価しません
- Steam以外もローカルの本体EXEを選択できます。Steam以外にSteamの検証操作を一律には勧めません
- 「その他」は共通事実の取得と相談案内だけ。通信/アカウント/音声/入力/全エンジン独自ログ/ハードウェア故障/保護されたアプリは専用解析の対象外です
- ゲーム名カタログによる自動認識ではありません。一般ゲームの名前はローカル表示だけで、レポート/履歴に保存しません
- ゲーム固有ルールは現在、本人が選択したSteam版Monster Hunter Wildsだけ。起動できない場合の専用プラン、同意した限定痕跡/CrashReport解析に対応。途中クラッシュ・性能症状等のプランは共通です

## 最短の使い方

1. ZIPのすべてを展開し、`Gemnao.Diagnostics.exe` と `.exe.config` が同じフォルダにある状態でEXEを通常起動します。ZIP内から直接起動しません
2. 「1 準備」で「診断するルール」は「PCゲーム共通（通常はこちら）」、困っている症状、配布元を選びます。分からない回答はそのままで構いません
3. 読み取り範囲を読み「読み取り範囲を確認し、このPC内での取得に同意する」→「自分で本体EXEを選ぶ」。ランチャーやクラッシュ報告用ではなく、実際のゲーム本体を選びます
4. すでに症状が出た後なら「すでに症状が出た場合: 直近10分を読む」。新しい再現は不要です。安全な再テストをする場合だけ「症状を確認する直前 → 記録開始」→普段の方法でゲームを起動し同じ短い場面を確認→「症状確認・レポート生成完了後 → 読み取る」
5. クラッシュレポート生成中は完了を待ちます。早く押して記録を取りこぼした場合、「起動し直さず、同じ記録を読み直す」。開始から最大30分、比較元/手順/本人結果を保持し、別の試行に数えません
6. 「3 次の一手」で事実と候補を確認し、未実施の手順を1つだけ自分で試します。状態を「自分で試した」→「1つ試したら → 同じ場面を再テスト」→本人の改善/変化なし等を記録。すでに試して変わらない手順は繰り返しません
7. 「4 詳細と保存」→「共有する内容を確認して保存」→全文プレビュー→「保存される全文を確認しました」→「ローカルにテキスト保存」。既定名は `gemnao-game-diagnosis.txt`

Steamの本体EXEは、ライブラリ→対象ゲームを右クリック→管理→ローカルファイルを閲覧から確認できます。複数EXEがあり不明ならゲーム公式へ確認します。ネットワーク/リンク/ジャンクション/保護されたアプリの場所を無理に開きません。

すでに遊べるなら失敗の再現や追加変更は不要です。履歴に実施した内容と本人結果だけを記録できます。PC全体の停止/電源断/再起動/ブルースクリーン/異常な発熱がある場合は再現させず、既存記録の取得とメーカー相談を優先します。

## 起動条件・保護機能

- 対象はWindows 11 x64 / .NET Framework 4.8以降。Framework4.8/4.8.1は通常Windows11に含まれます。SDK、追加インストーラー、PowerShellは不要です
- ARM64/32-bit Windows/Windows10は動作確認済みと扱いません
- 未署名です。SmartScreen/ウイルス対策/組織ポリシーで止められたら中止してください。保護機能の無効化/除外/警告回避/管理者実行による回避は案内しません
- 標準権限、昇格なし。常駐/サービス/自動起動/自己更新/設定の自動修復なし
- SHA256SUMS.txtは改変検出用で、発行元の署名や安全性認証ではありません

## 取得内容と上限

起動だけでは取得しません。同意後、検索/読み取りボタンを本人が押した時だけ処理します。独自のゲームフォルダ全走査や他アプリ一覧は取得しません。

### 共通のWindows情報

- OS版、CPU名/メーカー/論理プロセッサ（最初の1ソケット）、GPU名/メーカー/ドライバー版（最大8件）
- OS可視RAM/空きRAMと、RAMモジュール容量合計（最大16個）。シリアル等は照会しません
- Windows側と選択ゲーム側のドライブ文字ルートの容量/空き。SSD種別やマウント先を推定しません
- 選択EXEの版リソース。実行/ロードしません
- 選択EXEと、選択されたSteam.exeのAppCompatFlags Layers登録値だけ。HKCU/HKLM、32/64bit表示を読み、列挙/変更しません。登録と実際の有効設定/実効権限は別です
- Application Error1000 / Application Hang1002。パス完全一致と名前だけの一致を区別
- System Display4101 / Kernel-Power41はPC全体の参考記録で、ゲームとの因果関係は未確定
- 各ログは時間範囲内の最新300件まで。他アプリも上限に含まれ、取りこぼす場合あり。XML64KiB、固定フィールドのみ、DTD/外部実体禁止。未知形式/権限不足は不完全/不明
- WER1001、全文ログ、セーブ、子EXEの自動追跡は対象外。1000の版/例外/相対位置を比較しますが、`unknown`モジュールは識別欠落として完全パターンにまとめません
- 1イベント読取り3秒、ログごと15秒、WMI待機5秒。Windows API依存で総時間/即時キャンセルは保証しません

容量5GiB/5%、空きRAM1GiBは確認を促す本ツールの目安であり、ゲームの公式要件や故障判定ではありません。ドライバー版を「最新版」「原因」と自動判定しません。CPU/GPU名だけで性能合否は決めません。

### Steam側の追加確認（初期OFF、Steamを選んだ場合のみ）

「Steam本体を自分で選ぶ（追加確認用）」で実際の `steam.exe` を選びます。Wilds検索で関連付けた場合はその候補も利用可能。複数の登録先を勝手に同一扱いしません。

選択したSteam直下の固定6項目、OpenSteamTool.dll / cloud_redirect.dll / dwmapi.dll / xinput1_4.dll / localdwmapi.dll / opensteamtool.toml の存在/種類/Hidden属性だけ。本文/設定は読みません。

名前がsteamのプロセスを最大4個確認し、実際のEXEパスが選択されたものに一致するプロセスだけのモジュール一覧を取得します。最大1024件/プロセス、協調的10秒上限。一覧が一時的にメモリに入りますが、保持するのは固定5DLL名とSteam直下/Windows System32・SysWOW64/その他/不明の分類のみ。PID/タイトル/引数/アカウント/他アプリ一覧/一般実行メモリは記録しません。取得拒否/Steam未起動/競合は不明で、昇格しません。

存在、Hidden属性、Steamへの読込み、ゲームへの読込み、原因は別々です。Wildsの1事例だけで他ゲームの原因を認定しません。名前だけの削除/リネームやWindowsシステムDLL変更を案内しません。

### Wilds固有コースのみ

「Monster Hunter Wilds Steam版の固有ルール」を本人が選び、`MonsterHunterWilds.exe` を選択した場合だけです。名前と本人選択は発行元の真正性の証明ではありません。一般ゲームのZIPをCapcom形式として解析しません。

- 検索ボタンでSteamの登録先値/標準候補、libraryfolders.vdf最大1MiB、最大16ライブラリ、appmanifest_2246340.acf最大128KiBを限定確認。Steamuserdata/アカウントデータは読みません。登録ファイルのLastOwner等を一時的に読む場合も保存/利用/出力しません
- CrashReport直下の最大64項目からZIP有無/更新時刻を確認。追加同意がなければ中身は読みません
- 痕跡の追加同意: 本体直下のdinput8.dll / dxgi.dll / d3d11.dll / version.dll / ReShade.ini / reshade-shaders / reframeworkの7項目だけ。DLLは32MiB以下で既知の公開ツール名の版メタデータと照合。設定本文を読まず実行せず、名前だけでMOD導入/稼働/原因とは判定しません
- 同じ追加同意で製品版LastPlayedの時刻形式の有無だけ利用。クラッシュでも更新され得るため正常プレイの証拠にしません。体験版/βと製品版の本人回答は分離
- ZIP追加同意: 上限内の更新時刻が最も新しいZIP候補1個。または「別のCrashReport ZIPを選んで読む」で本人指定。8MiB/16項目/合計展開32MiB/1項目16MiB。異常圧縮率、暗号化/非対応形式、Zip64/分割、重複/移動パス/リンクを拒否。ディスク展開なし、実際の展開量も検査
- CrashReport.txtのProcess Information固定項目（UTF-8/64KiB）とMiniDump.dmpのヘッダー/例外/モジュールだけ（512モジュール/64ストリーム/名前2048バイト）。メモリに個人情報を含むバイト列が一時展開され得ますが、メモリ/レジスタ/スタック/命令は解析/保存/共有しません。DxDiag/event.evtx/systeminfo/config/EngineReport本文は対象外
- 古い/時刻不明/例外や版や位置が異なる資料を今回の1000や比較へ混ぜません。ダンプのゲーム名一致は選択実ファイルの同一性の証明ではありません
- Steam側とZIPの両方へ同意した場合だけ、ダンプに含まれる既知5名の位置分類を別時点のゲーム資料として追加。現在のSteamの読込みと混ぜません

## 履歴・対象の取り違え防止

「5 実施履歴と改善報告」で選択した手順/状態/本人結果を記録します。「実施の記録なし」は未実施の証明ではなく、解決は本人が選ぶまで補いません。観測された変化も操作実施や因果関係の証明ではありません。

対象EXE/ルール/症状を変えると、確認後に現在の比較・履歴を別診断としてリセットします。ゲームごとの質問も初期化し、前ゲームの実施済み回答を引き継ぎません。配布元/Steam関連付け変更では取得済み比較を破棄します。PC全体の安全注意は維持します。

任意の別同意後「このPCに履歴を保存」を押すと、次の専用場所へ保存します。

`%LOCALAPPDATA%\Gemnao\GameDiagnosis\history-v2.dat`

書込み中の一時名は `history-v2.tmp`。最大64件/平文XML32KiB、DPAPI CurrentUserで保護した後64KiB以下。固定のゲーム区分・症状・手順・状態・結果・限定観測と、履歴ごとの乱数を使った対象EXE場所の照合値を保存します。パスそのもの/アカウント/ハードウェアID/生ログは保存しません。照合値もTXT/JSONには含めません。これは端末識別ではなく、同じ場所でのファイル置換を検出する仕組みでもありません。

「保存した履歴を読む」は選択中EXEの場所・区分・症状が合う場合だけプレビュー→本人確認で復元します。古い観測を現在の比較基準にはしません。同じユーザーの他プログラム/侵害PCからの完全な秘密保護は保証しません。履歴は1件分の保存先で、保存時に前のものを置き換えます。

**0.4以前のWildsDiagnosis/history-v1は自動移行/読み込みしません。** 旧データは旧版の保存先に残ります。この版は旧版履歴を削除しません。必要なら旧版で確認し、対象を確かめて手順だけ本人が再入力します。

## 保存・共有・削除

- TXTは全文プレビュー/確認後に本人が保存先を選びます。対象名/パス/CPU・GPU製品名/ユーザー名/生ログ/端末ID/絶対時刻を固定選別で除外します
- 未知モジュール名はローカル表示のみ。公開名の固定リストのDLLも追加チェック時だけTXTへ出し、確認をやり直します
- **完全匿名ではありません**。選択肢、OS/ドライバー/RAM/容量/エラー分類等は残ります。スクリーンショットにはローカルの選択パスやCPU/GPU名が写る場合があります
- 一般ゲームの改善報告JSONは契約未対応で無効です。Wildsの「起動できない」コースだけ、最大8手順の固定v1JSONを全項目確認後にローカル保存できます。環境情報は別の任意選択。JSON保存は送信ではありません
- Web受付は準備中でボタン無効。自動アップロード、通信API、テレメトリー、AI呼出し、自己学習/更新はありません。本人確認後の公開ガイドを既定ブラウザーで開く場合のみ通常のWeb通信が起き、診断データをURLに載せません
- 同期フォルダへ保存するとOS/同期アプリが同期する場合があります。検査時に発見したネットワーク/リンク経由を避けますが、検査後の場所入替えに対する完全な耐性は保証しません
- 保存履歴は「保存履歴をゴミ箱へ」→アプリとWindowsの確認。完全削除になる警告なら取消。ゴミ箱を空にしません。画面内の履歴は残り、「新しい診断を始める」または終了で消せます
- アンインストール: 必要なTXT等を保管→不要なら上記の履歴削除→アプリ終了→展開フォルダとZIPを通常の方法でゴミ箱へ。展開フォルダ削除だけではLocalAppDataの履歴や別場所のTXT/JSONは消えません。利用者が保存した各ファイルを個別に管理してください

## 検証と再ビルド

Linux上で公式SDKからWindows向けEXEをビルドし、合成テスト/ソースガードを実施しています。Windowsの新UI、一般ゲーム実取得、DPI、Steamプロセス読取り、DPAPI履歴/ゴミ箱は実機未実行です。旧0.3の基本取得の所有者報告は0.5検証の代わりにはなりません。実物の個人ZIP/ログ/画像/パスは配布物に含めず、テストは架空データです。

開発者向け（利用者の起動には不要）:

    dotnet restore Gemnao.Diagnostics.csproj --locked-mode
    dotnet build Gemnao.Diagnostics.csproj -c Release --no-restore
    dotnet run --project tests/Core.Tests.csproj -c Release
    python tools/verify-source.py
    python tools/package.py

.NET SDK10、ビルド用Microsoft.NETFramework.ReferenceAssembliesを使用します。実行時の追加DLL/ランタイム再配布はありません。検証結果はdocs/BUILD-RESULTS.md、Windowsでの確認項目はdocs/WINDOWS-VALIDATION.mdを参照してください。
